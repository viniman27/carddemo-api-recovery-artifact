# T3 Campaign Adapter v1

Status: candidate/static preparation only. Official AWS campaign generated: false.

## Fixed in this adapter

- Uses `reference-executable-v4` traversal/guard/effect engine instead of synthetic transition BFS.
- Joins `transition.obligationRefs` to enriched T3 cells; it no longer treats `transition.id` as an obligation id.
- Uses authorized parametric recipes and fixture-bound selectors; blocked upstream cells have no request.
- Preserves the original P2a OpenAPI schema path and validates materialized request bodies against it.
- Uses `campaign-harness-v3` `Suite`, `Case`, `freeze_suite`, and `load_frozen_suite` for reusable generation.
- Removes broad invented expected HTTP statuses; contract checking is documented as a separate independent obligation.

## Supported limitations

- Static compatibility can inspect the real model without producing an official suite.
- Unsupported or non-eligible cells are blocked, not converted into requests.
- Transitions without joined cells are inconclusive, not failures or synthetic requests.
- Recipes do not prove guards; guard feasibility comes from the v4 reference engine.
- No official AWS cases are generated by default. A freeze path must be supplied explicitly by an authorized caller.
- Current real no-freeze materialization with the documented budget accepted 0 cases and blocked 90 selected cell joins; the dominant supported blocker is original P2a schema path incompatibility (`/posting`, `/interest`, `/reporting`) versus recipe operation paths (`/posting-runs`, `/interest-runs`, `/transaction-report-runs`). The adapter leaves these blocked rather than rewriting requests.
